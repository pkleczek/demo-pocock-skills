# 01: Actionable Problem Details for request-body failures

Status: resolved
Blocked by: None

Spec: ../spec.md

## What to build

Introduce global REST controller advice extending ResponseEntityExceptionHandler, with precedence over Spring Boot's default Problem Details handler. Implement safe structured body deserialization errors and Bean Validation errors across MVC controllers, retaining standard metadata and existing domain errors.

## Acceptance Criteria

- [x] Unreadable, malformed, and empty JSON bodies receive a useful body-level error when no field is identifiable.
- [x] Missing/null required Kotlin properties name the field; invalid typed values name the external field and describe the expected input safely.
- [x] Bean Validation exposes all available field and class-level errors, including existing custom constraint messages.
- [x] Errors use the existing field/message structure and never echo raw submitted values or framework internals.
- [x] Full-app HTTP tests exercise these behaviors through the established seam, using incremental red/green TDD.
- [x] Existing successful requests, domain rejection responses, and non-body error handling are preserved.
